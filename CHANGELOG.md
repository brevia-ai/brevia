# Changelog

All notable changes to this project are documented in this file. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and versions follow [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Added

- **Container image in the project template.** Generated projects get a `Dockerfile` (Python 3.12, uv, tini, installation from `uv.lock`, no secrets) and `bin/start`, which runs the worker and the HTTP API together (`APP_MODE=all`, the default), one of them (`api`, `worker`) or the migration (`migrate`). A stop reaches both processes and waits for them; when one ends on its own the container exits with an error. The `compose.yaml` of the project runs the image with the profile `app`. *Running in production* recommends the image, as one service or as two from the same image.

## [1.0.0b1] - 2026-10-19

First beta, for controlled use in internal projects: everything below is new. The
changes made while it was developed are recorded in the
[implementation log](docs/implementation-log.md); what the beta leaves out and what may
still change before 1.0 is on the [documentation home](docs/index.md#not-in-the-beta).

### Before installing

- **Database.** The initial migration changed during development: a database created
  with an earlier development version must be created again (or its `brevia` and
  `dbos` schemas dropped), then migrated with `brevia db upgrade`.
- **Models.** Verified with real calls on OpenAI (`openai:gpt-6-luna`, synthetic
  corpus of summary and extraction: 10/10 valid and faithful). Anthropic and Ollama
  are tested with simulated providers only.
- **Installation.** From the Git tag `v1.0.0b1` of the private repository; see
  [Running in production](docs/guides/production.md).

### Added

- **Defaults.** `brevia.config.defaults`: every functional default of the library in one module (maximum output tokens of a model use, attempts of a generation, run limits, `summarize` and `extract` settings, trace retention), each replaceable in the project file; the project file of the template writes them out. Neutral where the value is a choice of the project: no output limit, summaries in the language of the document, no token or tool call limit, contents of model calls kept without a time limit.
- **Core.** Error catalogue with stable codes, `retryable` and HTTP statuses (run failures `422`, `provider_error` `502`, `internal` `500`); installation settings (`BREVIA_*`); project file with declared models, limits and activity defaults; configuration composed from schema and project defaults, customisations and allowed request overrides; prompt templates with declared variables; structured generation through Pydantic AI with bounded retries and validators; run limits (requests, tool calls, tokens, time, `provider_retries`), `0` turning a limit off; only requests (20) and time (900 s) on by default; usage and cost estimates; logging helpers with run identifiers. Errors and log records never carry exception messages, provider bodies or input values.
- **Activities and direct runs.** `Brevia` with `register_activity`, `run` (with an optional `run_id`), `RunContext`; fake models for tests and local runs (`brevia.testing.fake_model`, `BREVIA_FAKE_MODELS`).
- **Models.** OpenAI (Responses API, `store: false`), Anthropic and Ollama, one client per provider and event loop; temporary provider errors retried by Brevia within the run limits, honouring `Retry-After`, billing errors of OpenAI and the spend cap and 402 of Anthropic never retried; reasoning levels up to `max` translated without silent substitutions; `max_tokens` not sent by default, so a response may reach the maximum of the model, reasoning included; `request_records` of every provider request in the record of a call, with the request identifier of OpenAI and Anthropic; the cost of a call unknown only when a request may have been billed without reporting its usage (an error answer of the provider, such as a rate limit, counts as no usage); a cancelled call counts the request in flight among the requests of the run, with an unknown cost; `reasoning = "max"` as effort `max` on Anthropic; options an adapter cannot apply refused, never replaced. `ModelSpec` also accepts a model reference alone, with the default options. Request options logged by the Anthropic SDK at the `DEBUG` level, which contain prompts and documents, are dropped.
- **Database.** PostgreSQL in a configurable schema with Alembic migrations (`brevia db upgrade`, `brevia db current`); `Brevia.start()`, `stop()`, `check()`; runs recorded with input, snapshot (with the versions of Brevia and of the application), outcome, usage and model calls with their options; contents of calls with `capture="full"`, expiring after `[traces] retention_days` (`0`, the default, keeps them); daily cleanup by the workers and `brevia db cleanup [--dry-run]`; development `compose.yaml`. Contents of model calls with `retention_days = 0` are recorded without an expiry and kept.
- **Customisations.** Configuration on `customizable` paths and prompts with their history: read, customise, reset, restore, with an optional `expected_version` (`VersionConflict`).
- **Jobs.** `Brevia.submit()` records and queues a job in one transaction; `RunHandle` (`status`, `result`, `cancel`, `retry`, `file`) and `JobState`; idempotency keys scoped to the caller and the activity; `brevia worker MODULE:NAME` on DBOS, with configuration and prompts resolved at the start; a job interrupted with its worker starts again from the beginning, at most 3 times; cancellation within about a second; releases with queued and interrupted jobs; `Brevia.jobs()` (`JobPage`, cursor pages) and `Brevia.find_job()`. Input and output recorded under the aliases of their fields, without computed fields, and read accepting aliases or names; a job whose output its schema cannot read back fails with `internal_error`, and one whose input its schema cannot read back is refused with `internal_error`. Idempotency keys of jobs and feedback share one check: a key with a NUL character is `invalid_input`, also when finding or listing jobs.
- **Files.** `FileSource` inputs from an allowed https host (or a local path for trusted code), checked and removed after the run; outputs saved as `FileRef` and read under the access policy; retention of files.
- **Documents.** `read_document` reads PDF (one section per page), DOCX (one section per heading, table cells separated by `" | "`) and UTF-8 text files into a `Document` of `Section` values, cleaned of NUL characters; damaged, encrypted, non-UTF-8 and textless files are refused without quoting their content. `ctx.files.read(source)` downloads and reads an input file in a thread; `Document.from_text`; `split(document, max_chars)` divides a document into `Piece` values that keep whole sections together and record the sections they come from. Dependencies pypdf and python-docx.
- **Analysis.** `brevia.analysis.map_reduce` (an output per piece, combined in rounds within `max_chars`) and `brevia.analysis.refine` (a result updated piece by piece through the `{previous}` variable), with the prompts of the activity, any output type, a validator at every step and the limits of the run. Ready activity `summarize` (`SummarizeRequest` with a file or a text, `SummarizeConfig` with `strategy` `auto` or `refine` and `max_input_chars`, `Summary`), its prompts in the package (`SUMMARIZE_PROMPTS`) and `summarize_document` for other activities. `extract(ctx, request, OutputType, validator=...)` for extraction activities with a schema of the project (`ExtractRequest`, `ExtractConfig`, `EXTRACT_PROMPTS`): one call, or `refine` over the pieces of a long document; `extract_document` for other activities. Optional rules of the project added to every call: `summarize_rules`, `extract_rules`, and `rules=` of the strategies. `SummarizeConfig.model` and `ExtractConfig.model` are a `ModelSpec`: an override may change one option, such as `model.reasoning`.
- **Tools.** `brevia.tools`: `Tool`, `generate(tools=...)`, scoped `read_file` with lossless pagination and `save_file`; typed arguments, corrections requested with `ToolRetry` (other errors stop the run), shared run budgets, offered names and counts in model-call records, outcome logs.
- **Access.** JWT authentication compatible with Brevia 0.15 (`Authenticator`, `AuthSettings`, `create_token`, `brevia token create`); `Caller` with an optional `end_user`; `AccessPolicy` (`per-caller` or `shared`, administrators).
- **Feedback.** `Brevia.add_feedback()`: corrections (`target`, `original`, `corrected`) or a rating (`good`, `bad`) with a comment, an external reference and a `source` (`user`, `reviewer`, `automatic`), only added; an idempotency key records a repeated submission once. Public types `FeedbackRequest`, `Correction`, `Feedback`.
- **HTTP API.** `brevia.api.create_app(brevia)`: one FastAPI app that starts and stops Brevia, gets the caller of each request from its Bearer token and answers every error as `{code, message, details, request_id}`; `BreviaDep` and `CallerDep` for the endpoints of an application. Endpoints: `/health/live`, `/health/ready`, `/status` (the token of a caller or `BREVIA_STATUS_TOKEN`, as in Brevia 0.15); `/activities`; `POST /runs` (direct: `{run_id, status, output}`, `422` with the `run_id` when the run fails; job: `202` with `Location` and `Idempotency-Key`), `GET /runs` (filters, cursor pages), `/runs/{run_id}` with `/result` (`409` until it succeeds), `/cancel`, `/retry`, `/files/{name}` and `/feedback`; `/configurations` and `/prompts` (writes by administrators). `end_user` in the body of the requests that record something. OpenAPI document with the real error body and the Bearer scheme. Dependencies FastAPI and uvicorn.
- **Project template.** `uvx copier copy --vcs-ref v1.0.0b1 gh:nikazzio/brevia-next my-project` generates an application with a custom text activity and the document summary activity, its worker, its HTTP API, a caller, tests with a fake model and a development database; `uvx copier update` takes the changes of the template.
- **Repository.** Package `brevia` (version `1.0.0b1`) with inline types, upper bounds below the next major version of every runtime dependency, documentation site, development rules, agent instructions and continuous integration.
